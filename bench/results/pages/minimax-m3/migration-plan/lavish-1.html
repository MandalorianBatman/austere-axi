Executive summary

Durable sessions without forced logout

Sessions currently live only in Redis and are lost on failover. Last month, that forced 38,214 users to log in again. The migration adds Postgres as the durable store while Redis remains a read-through cache.

Phased implementation

Four migration phases

    Create sessions table and dual-write

    1 week

    Add durable session storage while writes also continue to Redis.

  2. 2

    2 days

  3. 3

    1 week

  4. 4

    Remove Redis writes

    1 day

    End Redis writes while retaining Redis as a read-through cache.

Risk controls

Two identified risks

Login write latency

Mitigation: async write with a 50 ms timeout.

Table bloat from expired rows

Mitigation: nightly partition drop.
