ADR-017 Status: proposed

Event bus for order events

Decision to review: adopt Amazon SQS + SNS as the event bus for order events. Accept or reject below.

Context

The Orders service calls Billing, Shipping and Notifications over HTTP in sequence. One slow call blocks checkout.

Incidents last quarter
3
caused by this sequential calling

Options compared

Option Throughput Replay Ops cost Team experience
Kafka 1M msg/s Yes High we would run a 3-broker cluster None
NATS JetStream 200k msg/s Yes Medium One engineer
Amazon SQS + SNS Proposed Effectively unlimited No 14-day retention only Low managed High

Proposed decision: SQS + SNS

Orders publishes order.placed to an SNS topic. Billing, Shipping and Notifications each read from their own SQS queue.

Consequences (the cost of this choice)

No event replay

SQS + SNS keeps only 14 days of retention, so we keep an outbox table in the Orders database.

At-least-once delivery

Every consumer must be idempotent.
