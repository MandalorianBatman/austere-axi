ADR-017 Status: proposed

Event bus for order events

Proposed decision: use Amazon SQS + SNS. Orders publishes order.placed to an SNS topic; Billing, Shipping and Notifications each read from their own SQS queue.

Context

The Orders service calls Billing, Shipping and Notifications over HTTP in sequence. One slow call blocks checkout.

Incidents last quarter
3
caused by this pattern

Options compared

OptionThroughputReplayOps costTeam experience
Kafka 1M msg/s Yes High 3-broker cluster to run None
NATS JetStream 200k msg/s Yes Medium One engineer
Amazon SQS + SNS Proposed Effectively unlimited No 14-day retention only Low managed High

Proposed shape

Each consumer has its own queue, so a slow consumer no longer sits in the checkout call path.

Consequences

No event replay

SQS + SNS keeps messages for 14 days only, so we keep an outbox table in the Orders database.

At-least-once delivery

Every consumer must be idempotent.
