ADR-017 Status: proposed

Event bus for order events

Decision to review: adopt Amazon SQS + SNS so that Orders publishes one event instead of calling three services in sequence.

Context

The Orders service calls Billing, Shipping and Notifications over HTTP in sequence. One slow call blocks checkout.

Incidents last quarter
3
caused by this blocking behaviour

What changes

Today blocking

Calls run one after another. One slow call blocks checkout.

Proposed publish once

Orders publishes order.placed to an SNS topic. Billing, Shipping and Notifications each read from their own SQS queue.

Options considered

Kafka NATS JetStream Amazon SQS + SNS proposed
Throughput 1M msg/s 200k msg/s Effectively unlimited
Replay Yes Yes No 14-day retention only
Ops cost High we would run a 3-broker cluster Medium Low managed
Team experience None One engineer High

Consequences of the proposed decision

The costs of choosing SQS + SNS:

No event replay

We keep an outbox table in the Orders database.

At-least-once delivery

Every consumer must be idempotent.
