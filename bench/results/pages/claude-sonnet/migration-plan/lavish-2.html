Why and goal

Problem

Sessions live only in Redis and are lost on failover. Last month that forced 38,214 users to log in again.

Goal

  • Durable sessions
  • No forced logout
  • Auth p99 stays at or under 45 ms (today 41 ms)

Request path after the change

Sessions are stored in a new sessions table in Postgres. Redis stays as a read-through cache in front of Postgres.

Phases

  • Table + dual-write
  • Backfill
  • Switch reads
  • Remove Redis writes
