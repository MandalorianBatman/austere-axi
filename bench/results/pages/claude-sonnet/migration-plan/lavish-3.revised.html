Move user sessions from Redis to Postgres

Review the plan below, then approve it and pick a rollout strategy at the bottom of the page.

Why now

Sessions live only in Redis and are lost on failover. Last month that forced 38,214 users to log in again.

Goal

Durable sessions

Sessions survive a Redis failover.

No forced logout

Users stay signed in through the migration.

Auth p99 ≤ 45 ms

Today it is 41 ms.

Request path after the change

Postgres becomes the source of truth in a new sessions table. Redis stays as a read-through cache in front of it.

Phases

  • 1. Table + dual-write
  • 2. Backfill
  • 3. Switch reads
  • 4. Remove Redis writes
#PhaseDuration
1Create the sessions table and dual-write1 week
2Backfill existing sessions2 days
3Switch reads to Postgres behind the sessions_pg flag1 week
4Remove Redis writes1 day

Run back to back, the phases add up to 2 weeks and 3 days.

Risks and mitigations

Risk

Write latency on login

Mitigation: async write with a 50 ms timeout.

Risk

Table bloat from expired rows

Mitigation: nightly partition drop.

Risk

Connection pool exhaustion during the dual-write phase

Mitigation: put PgBouncer in transaction mode in front of Postgres.
